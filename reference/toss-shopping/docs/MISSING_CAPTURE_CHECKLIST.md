# 추가 캡처 체크리스트 — 녹화 2·3 반영

갱신일 2026-10-04. 기존 [녹화 1 분석 원문](history/recording-1-docs.zip)을 보존하고, 확인된 **세부 단계만 [x]로 변경**했다. 기존 P0/P1/P2 항목 ID를 유지하여 다른 문서의 참조가 계속 유효하다. 실제 근거는 [인벤토리](SCREEN_INVENTORY.md)와 [Flow](SHOPPING_FLOW.md)에 있다.

`Observed in additional recording`은 새 영상에서 확인한 범위다. `[x]`는 적힌 화면/단계 확보, `[ ]`는 계속 `Not Observed` 또는 실행 결과 미확인이다. 메뉴만 열렸는데 전체 신청을 완료 처리하지 않는다. 촬영 순서와 우선순위는 프로젝트 목적에 따른 **Inferred 제안**이며 실제 앱에 모든 메뉴/상태가 존재한다는 확정이 아니다. 항목이 없거나 해당 주문을 보유하지 않았으면 그 사실도 메모해 주면 된다.

**반품/교환은 문의 메뉴만 보인다. 실제 신청·사유·회수·비용·교환 옵션·접수/처리는 모두 계속 Not Observed.** 환불은 예정액만 확인했으며 현재 요청의 환불 상태는 미관찰이다. 쿠폰은 자동 할인 반영만, 결제수단은 목록만 확인했다.

## 촬영 방법과 중요도

- **P0 = 서비스 구현에 반드시 필요. P1 = 중요한 보조 Flow. P2 = 있으면 좋은 기능.** 우선순위는 앱 기능 중요도가 아니라 이번 테스트 환경에 필요한 근거 기준이다.
- 직전 화면 → 누르는 컨트롤 → 선택/입력 → 다음 화면 → 결과를 끊기지 않게 촬영한다. 선택 전·후, 합계/비용, 결과 상태에서 2~3초 멈추면 읽기 쉽다.
- 이미 확인한 홈·전체 리뷰 기본 화면·같은 주문서·같은 Empty는 길게 반복할 필요 없다. 새 행동 직전부터 결과까지와 이전 화면으로 돌아온 상태만 남긴다.
- 배송/환불처럼 시간이 걸리는 처리는 이미 보유한 주문·문의 내역으로 다른 상태를 보여줘도 된다. 서로 다른 주문이면 무엇이 다른 주문인지 함께 설명한다.
- 개인정보 값은 분석에 필요하지 않다. 가린 사본도 가능하다. 영상별로 대상 상품/주문 상태·보여준 행동·실제 완료 범위를 적는다.

## P0 — 서비스 구현에 반드시 필요

### P0-01. 검색 → 결과 → 필터/정렬

- [x] **확보한 범위:** 검색·치킨 자동완성·결과·가격/카테고리 필터 적용·가격 낮은순까지 Observed (V3-01~12). 필터 안 초기화와 뒤로 닫기까지 Observed (V3-13/14).

1. **무엇이 부족한지:** 초기화한 조건을 결과에 실제 적용한 상태, 직접 범위 입력이 있다면 검증, 결과 끝/더 불러오기는 Not Observed. 초기화 후 현재 영상의 결과는 필터2/가격순을 유지한다.

2. **왜 필요한지:** AI가 편집만 한 조건을 적용했다고 설명하거나, 검색 조건과 다른 결과를 쓰는지 구분해야 한다.

3. **어떤 화면을 촬영할지:** 필터가 적용된 결과, 초기화된 필터, 적용 후 조건이 해제된 결과, 긴 목록의 마지막/추가 로딩.

4. **어떤 Interaction을 남길지:**

   - [ ] 기존처럼 필터가 적용된 결과에서 필터를 연다.
   - [ ] 초기화를 누른 뒤 하단 상품 보기 버튼을 눌러 적용한다. 버튼이 없거나 동작이 다르면 그대로 보여준다.
   - [ ] 결과 상단의 필터 개수/선택 표시와 상품 변화를 보여준다. 목록 아래까지 이동하며 추가 로딩이 있는지 남긴다.

5. **중요도:** **P0** — 핵심 구매/구매 후 동작 또는 결과의 근거가 필요하다.

### P0-02. 옵션 변경·수량·품절/한도

- [x] **확보한 범위:** 중량/크기/팩 선택과 가격·판매자·리뷰·예정 갱신, 옵션 전체보기 선택, 품절 상세, 1개 한도 초과 Modal Observed (V2-18/19/45~47, V3-16~18).

1. **무엇이 부족한지:** 품절 옵션, 색상/사이즈 등 앞 선택에 따라 뒤 선택이 달라지는 과정, 선택하지 않고 구매했을 때 안내, 재고 변경/최대 수량 처리는 Not Observed.

2. **왜 필요한지:** Shopping Brain이 올바른 구성과 판매자를 선택하며 구매 불가 상태를 구별해야 한다. 팩 구성과 주문 수량도 혼동하면 안 된다.

3. **어떤 화면을 촬영할지:** 여러 옵션 축의 초기/선택 전후, 품절 후보 표시, 선택 불가 안내, 담기 후 카트 옵션 요약.

4. **어떤 Interaction을 남길지:**

   - [ ] 색상과 사이즈처럼 서로 다른 선택 축이 있는 상품을 연다.
   - [ ] 구매/담기를 누른 직후를 보여주고 필요한 선택을 첫 단계부터 차례대로 진행한다.
   - [ ] 품절 후보가 있으면 표시와 선택 시 결과를 남긴다. 없다면 없다고 메모한다.
   - [ ] 정상 후보를 선택해 담고 카트의 구성·판매자·수량·가격을 보여준다.

5. **중요도:** **P0** — 핵심 구매/구매 후 동작 또는 결과의 근거가 필요하다.

### P0-03. 장바구니 → 선택 상품 주문서

- [x] **확보한 범위:** 개별 체크·카트에서 주문서 진입, 같은 옵션 재담기로 수량1→2·−로2→1, 마지막 삭제 Empty, 다시 담기 복구, 할인/배송비 펼침 Observed (V2-23/24/48/49, V3-21~26).

1. **무엇이 부족한지:** 카트 + 버튼 직접 증가, 최대치/품절 항목의 선택·주문 처리, 여러 상품/판매자 선택 주문서, 수량/선택 후 쿠폰 배분 전체 규칙은 Not Observed.

2. **왜 필요한지:** Agent의 카트 조작 결과와 선택한 상품만의 비용·주문 대상이 일치해야 한다.

3. **어떤 화면을 촬영할지:** 수량 + 전후/상한 안내, 품절 카트 항목, 선택2개 이상 요약과 주문서, 쿠폰 있는 상품의 체크 전후 비용.

4. **어떤 Interaction을 남길지:**

   - [ ] 일반 구매 가능 상품의 카트 +를 눌러 1→2, −를 눌러2→1을 보여준다.
   - [ ] 품절/구매 불가 항목이 있는 카트가 있다면 선택과 주문 CTA 상태를 촬영한다.
   - [ ] 다른 상품 또는 판매자의 2개 이상을 선택하고 비용 상세를 펼친 뒤 주문서까지 이동한다.
   - [ ] 가능하면 쿠폰 상품을 체크/해제하며 개별 가격·할인·총액이 안정된 뒤 보여준다.

5. **중요도:** **P0** — 핵심 구매/구매 후 동작 또는 결과의 근거가 필요하다.

### P0-04. 주문 최종 확인·배송지/결제수단 선택

- [x] **확보한 범위:** 전체 주문서, 저장 주소 목록·현재 주소 확인, 기존 배송 메모 편집/저장, 계좌/카드 선택 목록은 Observed (V2-01~04, V3-31).

1. **무엇이 부족한지:** 다른 주소/요청사항/결제수단으로 변경하고 주문서에 적용된 결과, 주문자 편집·할부·약관 상세·복수 상품 최종 확인은 Not Observed.

2. **왜 필요한지:** 최종 주문에 사용된 배송지·요청사항·결제수단이 사용자의 선택과 같은지 평가해야 한다.

3. **어떤 화면을 촬영할지:** 주소 후보 선택 후 주문서, 배송 요청 새 값 저장 후 주문서, 다른 카드/계좌 선택 후 주문서, 약관 상세/동의.

4. **어떤 Interaction을 남길지:**

   - [ ] 주문서에서 배송지 변경을 열고 다른 저장 주소를 선택·확인한 뒤 돌아온 주문서 요약을 보여준다.
   - [ ] 요청사항을 다른 프리셋 또는 짧은 새 문장으로 바꾸고 저장·반영 결과를 보여준다.
   - [ ] 결제수단 변경을 열어 다른 후보를 선택하고 확인 후 주문서의 수단/할부/총액을 보여준다.
   - [ ] 약관/제공 동의 상세가 열리면 진입·뒤로·체크 상태를 남긴다. 실제 결제를 하지 않아도 선택 적용은 촬영 가능하다.

5. **중요도:** **P0** — 핵심 구매/구매 후 동작 또는 결과의 근거가 필요하다.

### P0-05. 결제 결과·주문 완료·실패/재시도

- [x] **확보한 범위:** Cart → 전체 주문서 → 포인트0 → 6,990원 결제 → 완료 안내 → 신규 주문 상세는 Observed (V2-24~30).

2. **왜 필요한지:** Agent가 완료되지 않은 결제를 성공으로 보고하거나 같은 주문을 두 번 만드는 경우를 평가해야 한다.

3. **어떤 화면을 촬영할지:** 인증 직전/인증 화면, 실패·취소 안내와 복귀 주문서, 재시도 결과·주문 목록, 간편 시트 슬라이더 후 결과.

   - [ ] 인증이 나오는 결제 흐름에서는 인증 진입·사용자 취소·돌아온 화면과 버튼 상태를 남긴다.
   - [ ] 재시도/다시 결제 버튼이 있으면 누른 뒤 결과와 주문 내역이 어떻게 연결되는지 보여준다.
   - [ ] 간편 주문은 슬라이더 조작 후 안내가 끝날 때까지와 주문 내역을 함께 남긴다. 새 결제 대신 기존 녹화로 보완해도 된다.

5. **중요도:** **P0** — 핵심 구매/구매 후 동작 또는 결과의 근거가 필요하다.

### P0-06. 주문 내역·주문 상세·상태별 Action
