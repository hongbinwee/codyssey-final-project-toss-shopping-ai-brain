# UI Pattern — 누적 관찰과 추가 패턴

갱신일 2026-10-04. 근거는 [SCREEN_INVENTORY.md](SCREEN_INVENTORY.md)의 130개 대표 상태와 전후 영상이다. 기존 패턴 설명은 아래 녹화 1 범위로 보존하고, 실제 확인 범위가 넓어진 행과 신규 패턴만 추가한다. `Observed`/`표시만`/`Not Observed`는 기능 결과의 확인 수준이며 설계 해석은 `Inferred`다.

**정확한 색상 코드·폰트명·폰트 크기·간격·모서리·논리 해상도·애니메이션 시간은 Not Observed**다. 880×1920은 영상 픽셀 크기. 아래는 구조/상태/동작의 분석이며 디자인 토큰을 임의로 만들지 않는다.

## 기존 UI 패턴 기록 — 녹화 1 범위

아래 원문은 최초 영상에서 확인한 패턴을 보존한다. 이 부분의 미관찰 문구는 녹화 1에 한정한다. 예: 검색/찜 목록/수량/Empty/리뷰 정렬은 위 추가 표에서 Observed로 갱신됐다.

| 검색형 홈 Header | H01~H04, BH01, OH01, C01, D01 | 검색 진입 영역·사용자 아이콘·장바구니 배지, 스크롤 축약 상태 | 아래로 탐색하면서 전체 영역이 사라지고 검색·장바구니 축약 아이콘이 상단에 노출; 위쪽으로 복귀하면 전체 영역 재노출 | 검색 입력·사용자 페이지 이동 결과 Not Observed |

## 후속 설계에 사용할 관찰 기반 구분 — Inferred

- 탐색 화면의 카드, 상세의 초기 팩 선택, 주문 시트의 구매 수량을 분리한다. **팩 구성**과 **구매 수량**은 다른 선택이다.
- 전체 선택, 배송 묶음 선택, 개별 상품 선택을 각각 기록하고 선택된 항목의 주문 합계와 함께 검증한다. 배송비 포함/포인트 사용 표시는 별도 금액 항목이 필요하다.
- 배송 예정, 실제 배송 상태, 반품 회수 상태는 별도 데이터다. 영상은 첫 번째만 확보했다.
- `Loading → Ready`, `Confirmation → Deleted`, `Added → Snackbar`처럼 원인·결과가 보이는 상태를 Wireframe에 반영한다. `Payment Slider Reset`은 성공/실패 대신 미확인 결과로 유지한다.
- UI 전환과 도메인 Action을 분리한다. 시트 열기·카드 제거 애니메이션·뒤로가기는 Agent가 수행할 주문/반품 요청의 성공 증거가 아니다.
- Skeleton/Modal/Toast의 모양은 관찰 근거로 삼고, 미확인 오류·품절·빈 상태의 외형과 정책은 추가 촬영 또는 프로젝트 요구 명세에서 별도로 결정한다.

정확한 동작과 미확인 상태를 확보할 순서는 [MISSING_CAPTURE_CHECKLIST.md](MISSING_CAPTURE_CHECKLIST.md)에 있다.

## 누적 상태 판정의 경계

Observed: 목록/상세/검색 이미지 Skeleton, 결제 CTA 로딩, Chat Skeleton, Cart Empty, CS 조건별 Empty, 삭제 확인/한도 Modal, 담기/삭제 Snackbar, 사유 선택·결제/취소 요청 결과. Disabled는 흐린 외형만 확인했다.

Not Observed: 일반 Error·Network Error·재시도·결제 Failure, 검색/찜/주문 전체 Empty, 단일 사진 확대, 실제 배송 Timeline, 반품/교환 처리 화면, 환불 진행, CS 메시지. 빈 가격 비교 본문·지속 Skeleton은 문구가 없어 에러로 확정하지 않는다.
